# 방송 주문 인터페이스 시안

서비스명은 **오렌담마켓 / ORENDAM**(축약명: 오렌담), 가상 판매자 이름은 **샘플옷장**이다. 청구·수취 화면의 셀러명을 플랫폼명으로 읽지 않도록 구분한다.

`index.html`을 브라우저로 열거나 이 폴더를 로컬 정적 서버로 열면 된다. 외부 라이브러리와 네트워크 요청이 없으며 운영 앱 빌드에 포함하지 않는다. `app.js`는 화면 체험용 모의 상태이고 실제 API, 인증, 결제 구현이 아니다.

## 권장 체험 순서

1. 손님 A에서 상품 옵션·수량 선택 → 내 구매 요청 → 예시 닉네임·위챗 ID 입력 후 저장.
2. 청구·입금 화면에서 **예시 중국 배송지**를 저장한다.
3. 상단 손님 B로 바꿔 같은 상품 목록에 주문이 섞이지 않는지 확인한다.
4. 방송 담당자 → 이름·가격만으로 상품 등록 (색상/사이즈 목록은 선택) → 구매 요청 마감 → 확보 수량·배송비 확인 → 청구서 발행.
5. 손님 A → 청구·입금 → 최종 내용 동의 → 위챗/알리페이 선택 → 예시 증빙 사용 → 입금 확인 요청.
6. 입금 확인자 → 실제 수취 금액과 **가상 거래 식별자** 입력 → 대조 체크 → 입금 확인 완료.
7. 고객 화면에서 확인 완료를 확인한다. 담당자에서 예시 배송 정보도 등록할 수 있다.

청구 화면을 바로 보고 싶으면 아직 주문이 없는 손님의 청구·입금 탭에서 ‘시안: 청구서 예시 불러오기’를 누른다. ‘실패 상황 체험’을 체크하면 예시 증빙 저장 실패 → 재시도를 확인할 수 있다. 수금 확인자는 ‘추가 확인 요청’으로 고객에게 보완 사유를 보낼 수 있다(실제 메시지 전송은 없음).

## 현재 한계

- 새로고침/처음부터는 모든 상태를 초기화한다. 영구 저장·실제 손님 구분·접근 제어·업로드·송금은 없다.
- 실제 파일 선택도 브라우저 내 미리보기만 한다. 개인정보가 들어간 실제 증빙 대신 예시 버튼을 권장한다.
- 시안은 첨부 1장을 체험하며 실제 계약은 최대 3장이다. 원본 증빙 이력·다운로드 권한은 후속 서버에서 구현한다.
- 수금 대조 시각·송금자 상세 입력, 주소 개별 성/시/구, 거래정보만 제출하는 보조 양식, 복구, CSV, 환불은 [화면·API 계약](../../plans/broadcast-orders/interfaces.md)을 따른다. 시안의 단순화가 계약을 축소하지 않는다.
- 상품 화면은 사진 없이 번호·이름·가격으로 표시한다. 예전 시안의 상품 그림은 사용하지 않는다. 송금 증빙 첨부는 별개로 유지한다.
- 역할/손님 전환은 검토 도구이며 실제 제품 UI에 포함하지 않는다. 실제 권한·동시성·중국 회선 성능을 이 시안 결과로 보증하지 않는다.

## 상품을 잘못 등록했을 때

- 구매 요청 접수 이력이 없는 상품만 ‘수정’에서 이름·가격·옵션을 바꿀 수 있다. 수정 사유를 남긴다.
- 손님이 담기만 하고 저장하기 전에 담당자가 수정하면, 손님의 내 구매 요청에 변경 전후가 표시되고 저장 버튼이 잠긴다. ‘변경 내용 확인’ → 현재 옵션 재선택 → ‘변경 내용 확인하고 담기’ → 요청 저장 순서로 진행한다. 변경에 동의하지 않으면 ‘이 상품 빼기’를 누른다. 수량은 재확인창에 유지된다.
- 주문 이력이 없으면 ‘삭제’ → 사유 → 확인으로 고객 목록에서 숨긴다. ‘삭제한 상품’에서 복구하면 판매 중지 상태이며 확인 후 재개할 수 있다.
- 접수 이력이 한 건이라도 생기면 수정 버튼이 잠기고 삭제 버튼이 사라진다. ‘요청 접수됨 · 정보 고정’ 사유를 표시한다. ‘판매 중지’로 기존 요청을 남기고 신규 접수를 막는다. 취소된 요청도 이력에 포함하며 모두 취소해도 수정 잠금은 풀리지 않는다.
- 접수 후 정정은 판매 중지 후 고객별 정정 청구로 안내한다. 금액/수량/배송비 정정, 변경 사유·전후 비교, 고객 동의/수정 요청, 재발행과 이전 청구 이력을 체험할 수 있다. 다른 상품으로 교체하는 주문과 실거래 취소는 후속 범위다. 고객의 전체 제외 요청에 따른 미송금 취소 화면은 v1.4 시안에 포함한다.
- 번호는 삭제 후에도 재사용하지 않는다. 새로 등록하면 항상 새 번호다.
- 색상/사이즈 선택 목록을 생략한 상품에서는 고객이 옵션을 직접 적을 수 있다. 사진 촬영은 요구하지 않는다.

## 정정 상황을 바로 체험하려면

1. 상단 **정정 상황 체험**을 누른다. 가상 손님 A와 원 청구 ¥188, 정정 청구 ¥208로 초기화한다.
2. 고객은 개당 ¥88 → ¥98, 최종 ¥188 → ¥208, 정정 사유를 확인한다. ‘동의하고 송금 안내 보기’를 누르려면 확인 체크가 필요하다.
3. ‘동의하지 않아요 · 수정 요청’ → 사유 입력 → 미송금 확인 → 요청을 남긴다. 송금 안내는 닫히며 주문은 자동 취소되지 않는다.
4. ‘방송 담당자’ → 손님별 요청·청구의 ‘청구서 정정’ → 단가/수량/배송비와 사유를 작성 → 총액 확인 → 정정 청구서 발행.
5. ‘손님 화면’에서 새 청구를 확인해 다시 동의한다. 이전 청구는 이력으로 보존되고 송금할 수 없다.

고객이 이미 송금 안내를 연 청구서는 담당자의 직접 정정이 잠긴다. 아직 송금하지 않은 고객은 ‘송금 전 청구 수정 요청’으로 재확인을 요청할 수 있다. 증빙이 연결되었거나 입금 확인이 시작된 건은 이 경로에서 정정하지 않는다. 실제 메시지/계좌 연결/환불은 없다.

## 상품별 제외와 전체 취소 체험

1. **상품 제외 체험**을 누르면 니트 2개·셔츠 1개, 정정 청구 ¥316으로 초기화한다.
2. 고객이 상품의 **이 상품 제외 요청**을 누른다. 상품·색상·사이즈별 대상과 제외/미송금 여부를 확인한다. 다른 상품도 함께 선택할 수 있다.
3. 일부만 요청한 경우 **방송 담당자 → 제외 요청 반영하기 → 해당 항목의 청구에서 제외**를 누른다. 아직 작성 중이므로 이 단계만으로 고객 청구서는 바뀌지 않는다.
4. 남은 상품의 배송비를 확인하고 체크한 뒤 변경 사유를 적어 새 청구서를 발행한다. 고객은 포함 상품과 ‘청구에서 제외된 상품’을 따로 확인하고 새 금액에 동의한다.
5. 현재 청구된 상품을 전부 제외 요청하면 담당자에게 **전체 주문 취소 확인**이 표시된다. 대상·사유·미송금 확인 → **주문 취소 확정** 후 고객과 담당자 화면이 취소 완료로 바뀐다. 0원 청구서는 발행하지 않는다.

이전에 이미 제외된 항목은 다시 선택하지 않아도 된다. 일부 제외 요청을 전체 취소로 확대할 수 없으며 고객 요청을 반영하지 않은 재청구도 막는다. 기존 요청·청구·상품 접수 이력은 남는다. 고객이 송금 안내를 열었더라도 미송금 확인을 거친 제외 요청만 허용하고, 증빙/입금 확인이 진행 중이면 이 경로를 사용하지 않는다. 모든 처리는 시안의 가상 데이터다.
