# 오렌담 방송판매 시스템 개발 착수 요구사항 v1

접수: 2026-09-23 · 출처: 판매자 인터뷰를 마친 사용자가 전달한 51개 절. 아래는 원문 번호를 유지한 정리본이며 개발자의 추가 결정은 [설계](README.md)에 분리한다. 과거 v1.4보다 이 문서가 우선한다.

## 1. 목적
추가 기획 인터뷰보다 MVP 개발 착수가 목적이다. **확정**은 구현 기준, **제안**은 더 나은 구현으로 대체 가능, **미확인**은 개발을 막지 않고 실제 중국 고객/기기/외부 서비스로 확인한다.

## 2. 정의
라이브는 더우인. 오렌담은 상품 준비 → 주문 → 고객 관리 → 정산 → 입금 → 거래처 발주 → 입고/미송/불량교환 → 부분/전량 출고 → 송장을 연결한다. 종이 기록 후 엑셀 재입력을 없애고 한 주문 데이터를 끝까지 사용한다.

## 3. 현재 운영
진행자가 코디·가격·사이즈 소개 → 더우인 채팅 주문 → 보조가 종이 기록 → 방송 후 엑셀 → 고객별 정산서 → 송금 캡처 → 수취 확인 → 입금완료분 거래처 합산 발주 → 부분/전량 입고 → 미송/불량교환 → 고객별 부분/전량 출고 → 실제 출고 상품 영상과 송장 위챗 전달.

## 4. MVP 방향 (확정)
방송 중 고객 웹 주문을 강요하지 않는다. 고객은 채팅, 보조는 휴대폰으로 오렌담 입력. 방송 후 고객 웹에서 주문 조회·추가·수정 요청·정산서·주소·송금 안내·캡처 제출·배송/송장을 제공한다.

## 5. 역할
현재 운영자 2명. 진행자는 소개/코디/방송 담당이며 주문 입력은 기본 업무가 아니다. 보조는 채팅 확인·휴대폰 입력. 판매자/관리자는 정산·입금·발주·입고·미송·교환·출고. 한 사람이 여러 역할 가능. 과도한 직원 권한 체계 제외.

## 6. 방송
ID, 날짜, 이름, 종류, 판매자 설정 환율, 한국/중국 기본 배송비, 택포 조건, 주문 집중 관리기간, 상태. 기본 배송비 한국 4,000원 / 중국 30위안. 실시간 환율 대신 판매자 수동 입력.

## 7. 종류
신상: 사전 전체 상품 등록. 특가: 현장 확인 후 빠른 등록. 둘 다 지원.

## 8. 상품
ID, 자동 번호, 거래처, 제품명, 가격, 기본 사이즈, 컬러, 공개 여부/순서, 수량 제한 여부/판매 가능 수량, 택포 계산 제외 여부. 사진 필수 아님. 번호+짧은 이름 권장(27번/데님조끼).

## 9. 공개
미소개 상품 비공개. 실제 소개 상품만 공개. 현재 코디에 A 상의+F 하의처럼 여러 상품 동시 노출. 고객 상단 현재 코디, 하단 오늘 소개한 상품. 이전 소개 상품도 계속 조회. 카드 최소 번호/이름/가격.

## 10. 빠른 입력
모바일 우선. 고객 검색 → 상품 → 컬러 → 사이즈 → 수량 → 저장. 더우인 닉네임 부분 검색(몽 → 몽이맘/몽베베/몽실이).

## 11. 저장
동일 고객·상품·옵션도 반복 주문은 별도 행. 자동 합산 금지. 정산/통계에서만 합계 계산. 건별 원본 유지.

## 12. 출처
방송 보조 입력, 고객 직접 추가, 판매자 입력, 판매자 수정은 자동 기록. 메모는 M→L 요청·품절 제외·불량교환 등 특이사항용.

## 13. 고객
신규 고객은 위챗으로 더우인 닉네임을 알려주며 판매자는 위챗 연락처 이름을 그 닉네임으로 관리. 내부 고객 ID, 더우인 닉네임, 위챗 식별/관리 정보, 선입금, 배송주소, 고객 전용 링크. 닉네임은 PK 아님.

## 14. 선입금
첫 거래 거파 방지 10,000원. 최종 정산에서 명시 차감(80,000-10,000=70,000원).

## 15. 고정 링크
고객별 고정 링크를 위챗으로 한 번 전달, 잃으면 재전달. 가입·비밀번호 필수 아님. 향후 인증 확장 가능. A가 B의 주문/주소/정산/결제정보 열람 불가. 고정 URL만으로 개인정보 전체가 노출되지 않도록 개발자가 보안 설계.

## 16. 추가 주문
당일+이후 2~3일 집중 지원. 시즌 한 달 중 이후 소량은 수기 처리 가능. 고객이 상품 선택 후 ‘검정 M 하나’, ‘핑크 7호 두개’ 한 줄 입력. 많은 옵션 버튼 요구 금지. 운영자가 정산 전 정리 가능.

## 17. 수정·취소
입금 전 가능. 고객은 원본 편집 대신 수정 요청 → 관리자 알림 → 관리자 반영. 입금 후 변경·취소 불가. 송금 전 제품명/색상/사이즈/수량 확인과 변경·취소 불가 경고. 판매자 입력 실수도 입금 전 수정 가능. 고객에게 최종 내용 중심, 내부 변경 기록 권장.

## 18. 부족 수량
먼저 주문한 순서로 배정. 생성시간/원 주문순번 필수. 미확보 상품만 제외, 전체 고객 주문 취소 금지.

## 19. 정산서
제품명, 컬러, 사이즈, 수량, 단가, 선입금 차감, 배송비, 최종금액. KRW/CNY 모두 표시. 방송/정산의 판매자 설정 환율 사용.

## 20. 택포
대표 신상 5장, 실외복 6장. 방송별 기본 배송비/기준 수량/제외 상품 설정. 복잡한 프로모션 엔진 제외.

## 21. 주소
초기 고객 등록 시 요구하지 않는다. 정산서 발행 후 신규 입력, 기존 주소 표시. 입금 전 고객 변경+관리자 알림. 입금 후 판매자에게 요청, 판매자가 변경. 출고 당시 주소 스냅샷 불변.

## 22. 송금
결제 API 제외. 한국 계좌/위챗페이/알리페이 기존 경로. 고객이 KRW 또는 CNY 선택.

## 23. 증빙
송금 → 캡처 → 확인 대기 → 실제 수취 대조 → 완료. 캡처로 자동 완료 금지. 대리 송금 허용, 고객명과 송금자명 일치 강제 금지.

## 24. 복수 입금
정산서 1:N 입금. 320위안 청구에 300+20으로 완료. 초과분 판매자 환불. 단일 paid 불리언 금지.

## 25. 미입금
발행 후 3일 입금 없으면 취소 대상. 자동 취소 금지. 관리자 홈 미입금/취소 확인 필요 표시. 자동 독촉 제외.

## 26. 발주
입금완료 주문만 거래처+상품+컬러+사이즈로 합산. 고객별 발주 아님.

## 27. 거래처 발주표
고객 개인정보 제외. 거래처/제품명/컬러/사이즈/발주수량/이번 입고/누적 입고/잔여 미송/메모. 필요 시 엑셀 다운로드.

## 28. 고객관리표
내부 전용. 거래처/제품명/컬러/사이즈/수량/주문자명/입금확인/현재상태/메모. 발주표와 같은 주문 데이터의 다른 View.

## 29. 입고
복수 입고 지원. 발주10 → 입고6/미송4 → 추가2/누적8/미송2. 발주/이번/누적/잔여 구분.

## 30. 배정
부분입고는 입금순 아닌 원 주문순 배정. 자동 배정안을 관리자가 확인하는 방식은 제안.

## 31. 미송
새 주문을 만들지 않고 기존 주문 잔량 유지. 입고 시 해당 수량 상태 변경.

## 32. 불량교환
입고 불량은 출고 금지, 거래처 교환 요청. 미송과 별도 상태.

## 33. 내부 상태
주문/라인 분리 권장. 접수, 정산대기, 입금대기, 확인대기, 완료, 발주, 미송, 입고, 불량교환, 부분/완료 출고, 취소.

## 34. 고객 상태
주문 확인/입금 확인/상품 준비 중/부분 출고/출고 완료로 단순화. 미송·불량교환은 준비 중으로 표시.

## 35. 장기 미송
발주일 기준 14일 초과, 고객별 먼저 표시. 상세 상품/색상/사이즈/거래처/발주일/경과일.

## 36. 출고
부분 출고, 여러 송장. 출고 ID/고객/포함 라인/출고수량/일자/주소 스냅샷/송장/부분 여부.

## 37. 분리 배송비
미송으로 인한 2·3차 배송비는 판매자 부담. 고객 추가 청구 금지.

## 38. 영상
위챗 영상/송장 전달 유지. 오렌담 동영상 기능 제외. 출고상품/일자/송장/잔여상품만 표시.

## 39. 알림센터
수정 요청/추가 주문/주소 변경/증빙/3일 미입금/취소 확인/14일 미송. 읽음 아닌 처리 여부 중심.

## 40. 고객 화면
공개 상품/오늘 상품/내 주문/한 줄 추가/수정 요청/정산서/주소/송금/증빙/준비상태/부분출고/송장. 클릭 최소화.

## 41. 운영 화면
대시보드, 방송·상품관리, 모바일 입력, 고객별 주문, 정산, 입금, 발주, 입고, 고객관리표, 출고.

## 42. P0 (시험 운영 전 필수)
고객 등록/검색/고정 링크, 방송 생성/사전·빠른등록/공개/현재 코디, 모바일 입력/건별 관리, 고객 조회/한 줄 추가/수정 요청, 선입금/정산/환율/택포/주소/경고, 증빙/수동 확인/복수 입금/3일 알림, 합산 발주/발주표/고객관리표, 부분입고/미송/교환/14일 알림, 부분출고/복수 송장/알림센터. 이 전체를 P0로 부르며 이전 계획의 ‘P0 기반 확인’과 다르다.

## 43. 후순위
엑셀 포맷 고도화, 수량 제한 자동 품절, 입고 자동배정 UX, 고객 UI 개선, 상세 통계, 고급 권한.

## 44. 제외
자체 방송, 위챗 자동 메시지, 위챗/알리 결제 API, 은행 자동대조, 고객 비밀번호, 출고영상, 한 달 전체 자동화, 쿠폰/포인트/등급, 복잡한 WMS.

## 45. 기존 대비 변경
방송 중 고객 웹 강제→직원 모바일. 단일 현재 상품→다중 코디. 현장등록만→신상 사전/특가 현장. 빠른 마감→2~3일 추가. 고객 원본 편집→요청 후 관리자 반영. 주소 조기수집→정산 발행 후.

## 46. 모델 유의
같은 옵션도 독립 라인; 정산:입금=1:N; 고객 주문:출고=1:N; 내부·고객 상태 분리; 현재·출고 주소 분리; 생성 순서 영구 보존.

## 47. 실기기 미확인
중국 VPN 없는 iPhone/Android, 위챗/일반 브라우저, 이동통신망; 고정 링크 보안 UX. 더우인 링크/동시 사용은 핵심 흐름의 전제 아님. 위챗 자동알림·알리 자동연동은 후속. 개발 차단 사유 아님.

## 48. 필수 시험 (1~30)
1 방송 생성, 2 환율/배송/택포, 3 신상 사전등록, 4 A 공개, 5 코디 F 추가, 6 모바일 보조 입력, 7 동일 재주문 별도 행, 8 고객 링크 조회, 9 한 줄 추가, 10 사이즈 요청, 11 관리자 반영, 12 정산, 13 신규 주소, 14 입금 후 변경불가 경고, 15 캡처, 16 부족입금, 17 추가입금, 18 입금완료, 19 거래처 합계, 20 발주, 21 10중6 입고, 22 주문순 배정, 23 잔여4 미송, 24 불량교환1, 25 부분출고, 26 송장, 27 잔여출고/두번째 송장, 28 미입금3일, 29 미송14일, 30 중국 실기기 전 고객 경로.

## 49. 성공 기준
동일 주문 재입력 0회. 상품당 약20건에도 진행자가 입력을 기다리지 않음. 고객 주문과 발주합계 일치(취소/미입금/추가 발주대기 차이는 명시). 모든 라인 접수→출고 추적. 타 고객 개인정보 노출 0건.

## 50. 판단 순서
방송 지연 방지 → 반복 입력 감소 → 고객 클릭 감소 → 처음부터 출고까지 추적.

## 51. 착수
인터뷰 완료. UI/DB/API/보안/기기검증/시험방송에서 남은 결정을 진행. 요구 확정 → 화면/상태 → DB → API → P0 티켓 → 구현 → 시험 → 수정. 각 단계 재승인 인터뷰로 되돌리지 않는다.
