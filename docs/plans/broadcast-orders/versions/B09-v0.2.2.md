# B09-v0.2.2 · 테스트 Cloud 고객 게이트웨이 연속 검증

- 기록: 2026-09-29. 상태: **진행 중**. 공통 문서 v2.2.0. 이전 [v0.2.1](B09-v0.2.1.md)의 테스트 프로젝트 스키마·Auth·QR 검증을 유지한다.
- 사용자 승인으로 격리된 `orendam-broadcast-test`의 기존 서버 전용 키를 대시보드에서 읽어 시험 프로세스 메모리에만 전달했다. 키는 채팅·저장소·로그에 남기지 않았으며 새 키를 만들거나 운영 프로젝트에 접근하지 않았다. 임시 익명 로그인은 앞선 시험 직후 꺼 둔 상태에서 기존 두 Auth JWT를 사용했다. 종료 후 키 표시·클립보드·프로세스 참조를 비우고 `/tmp`의 임시 JWT fixture도 삭제했다.
- `cloud-preflight-check.mjs`가 실제 Cloud와 로컬 고객 게이트웨이를 연결해 통과했다. 고정 URL만의 접근 거절, 판매자 승인과 pending 기기의 결합, 승인 토큰 단독 사용 거절, 고객 A/B 세션 분리, 청구별 비공개 QR 다운로드, 중국 주소 등록·청구 최종확인, 실제 private Storage 증빙 2건 업로드, 두 번의 **가상** CNY 수취 확인·합계, 미입금 발주 제외와 입금 후 거래처 발주 합산·확정, 정상 1개 부분입고·원 주문 배정·잔여 미송 1개, 부분출고와 고객 송장 조회를 확인했다. 상품 주문은 동일 옵션 2행으로 유지됐다.
- 객체 업로드 후 publishable key만으로 익명 고객 테이블·직원 workspace가 거절되고 두 private 버킷 목록에 객체명이 드러나지 않음을 다시 확인했다. 별도 QR 객체의 익명 다운로드도 거절됐다.
- 이는 HTTP/RPC/Storage 자동 통합 시험이다. 실제 Flutter 고객·직원 화면의 클릭 경로, 카카오 복귀·실제 두 휴대폰, 한 방송의 요구사항 §48 30단계 현장 수행, 연길 무VPN iPhone/Android 접속은 미실시다. 실계좌 송금·고객 메시지·운영 DB/웹 배포는 하지 않았다. B09 `v1.0.0` 완료로 표시하지 않는다.
