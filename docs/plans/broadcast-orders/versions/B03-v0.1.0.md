# B03-v0.1.0 · 청구·선입금·주소 첫 구현

- 기록: 2026-09-28. 상태: **진행 중**. 공통 문서 v2.2.0.

## 구현

- `202609280006_broadcast_billing.sql`: 배송국가, 확인 선입금 원장, 청구 판본/행 스냅샷, 선입금 배분, 고객 주소 버전. 관리자 명령은 권한·멱등키·판매자 잠금을 검사한다.
- 청구 발행 시 미청구 주문을 잠그고 상품금액·택포 수량·배송비·판매자 환율을 고정한다. 선입금 잔액만 배분하고 다른 청구에서 다시 차감하지 않는다. 이후 방송 설정이 바뀌어도 발행 청구 금액은 유지된다. 추가 주문은 별도 새 청구로 발행할 수 있다.
- 고객 기기는 본인 청구만 조회하며 내부 거래처/직원 정보를 받지 않는다. 발행 뒤 주소를 버전 검사로 저장하고, 주소가 있어야 최종 확인할 수 있다. 입금 잠금 뒤 직접 주소 변경은 거절한다. 게이트웨이와 고객 Flutter 화면에 청구/주소 경로를 연결했다.

## 검증

- PGlite: 다른 판매자 거절, 거래참조 중복 차단, 24,000원 상품+4,000원 배송−10,000원 선입금=18,000원 청구, 200원/위안 기준 90위안, 멱등 재시도, 중복 발행 거절, 환율 변경 후 스냅샷 불변, 본인 기기 청구 조회, 타 고객 격리, 주소 전후/버전/입금 잠금.
- 로컬 게이트웨이 HTTP에서 billing/address/accept 쿠키·범위를 검증했다. 실제 PostgreSQL/PostgREST 마이그레이션 회귀 통과.
