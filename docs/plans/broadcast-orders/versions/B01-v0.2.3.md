# B01-v0.2.3 · 실제 Cloud Auth 두 사용자 검증

- 기록 시점: 2026-09-28T15:56+09:00. 상태: **진행 중**. 공통 문서 묶음: v2.2.0. 이전 [B01-v0.2.2](B01-v0.2.2.md)는 변경하지 않는다.

## 변경

- 사용자가 승인한 별도 Cloud 테스트 프로젝트에서 익명 로그인을 잠시 켜 판매자·보조 두 Auth 사용자를 만들고, 검증 후 다시 껐다. 이 계정들은 테스트 전용이며 운영 NAS와 무관하다.
- `cloud-auth-create.mjs`, `cloud-auth-check.mjs`, `cloud-adapter-check.mjs`를 추가해 실제 Auth 발급 JWT와 Cloud PostgREST, Flutter `SupabaseBroadcastRepository`의 경로를 재현 가능하게 했다. URL·publishable key·Auth 토큰은 저장소에 넣지 않는다.

## 실제 검증

- 참여 전 판매자 workspace는 manager, 보조 접근은 403. 일회용 코드로 보조가 참여한 뒤 assistant 권한 확인. 보조의 관리자 전용 방송 생성은 403.
- 보조 주문과 동일 키 재시도는 1행. 판매자·보조 두 Auth JWT로 추가 20건 동시 저장 시 ID/순번 고유, 출처는 각각 seller_input/broadcast_assistant. 주문 원본, 고객·주문 페이지, workspace의 `has_orders` 확인.
- 판매자가 보조 권한을 회수한 뒤 보조의 workspace·주문 명령은 403, 판매자는 계속 접근 가능.
- 실제 Flutter `SupabaseBroadcastRepository`를 Cloud Auth JWT→Cloud RPC에 연결해 조회·주문 저장/재시도·회수된 사용자 거부 통과. 별도 로컬 어댑터 시험도 재통과.
- 익명 로그인은 설정 저장 후 페이지 재로드에서 **꺼짐** 확인. Auth 세션 임시 파일은 검증 후 삭제한다. Cloud 테스트 DB에는 시험용 사용자/주문 데이터가 남는다.

## 미검증·다음 게이트

- 이번 Flutter Cloud 시험은 Auth 발급 JWT를 저장소에 주입한 격리 테스트다. 기존 앱의 카카오 로그인 화면·로그인 리다이렉트, 두 실제 휴대폰의 참여 링크·회수 직후 화면 반응, 실제 프로세스 종료/재시작과 상품당 약20건 입력 속도는 남았다. 따라서 B01-v1.0.0이 아니다.
- 운영 DB 적용·배포·실거래·고객 메시지 없음. B02~B09 실제 구현은 별도 단계.
