# B02-v0.2.0 · 고객 추가·수정 요청과 관리자 검토

- 기록: 2026-09-28. 상태: **진행 중**. 공통 문서 v2.2.0. B01은 v0.2.4 진행 중.

## 구현

- `202609280005_broadcast_customer_requests.sql`: 승인된 기기의 고객만 한 줄 원문을 추가주문/수정요청으로 접수한다. 같은 요청 키 재시도만 멱등, 추가주문은 요청 시 원 주문 순번을 예약한다. 관리자가 옵션/수량을 확인하고 승인 또는 사유와 함께 반려한다. 원문·원 주문순번·주문 스냅샷·감사 기록을 보존한다.
- 같은 출처 게이트웨이에 고객 요청 조회/접수 API를 추가했다. 브라우저에 service-role 키를 노출하지 않는다.
- Flutter 고객 링크 화면과 관리자 기기 승인·회수·요청 검토 화면을 추가했다. 고객 링크 발급·승인 링크는 관리자가 기존 위챗 대화로 수동 전달한다. 앱 기능 플래그가 켜진 빌드에만 경로가 열린다.

## 검증

- PGlite: A/B 격리, 원문/키 재시도, 관리자 승인 시 독립 주문행·예약 순번, 수정 시 원본 보존, 반려 사유, 오래된 버전/입금 잠금 거부.
- 로컬 게이트웨이 HTTP: 고객 쿠키/동일 출처 검증 및 A/B 요청 격리.
- PostgreSQL 15 + PostgREST에 005 증분 SQL 적용 및 기존 B01/B02 HTTP 회귀 통과.
- Flutter 정적 분석 문제 0건, 기능 플래그 웹 빌드 통과.

## 미검증·다음 게이트

- 실제 고객·관리자 Flutter 화면의 동일 출처 게이트웨이 연속 조작, 링크 재방문/활성화, 모바일 입력 UX, 관리자 처리함 통합은 미검증이다. 고객 링크 UI는 현재 고객 ID 수동 입력을 통한 발급이다.
- 청구 판본 발행 후 수정 요청의 재발행 흐름은 B03에 연결해야 한다. 현재 관리자는 발행된 청구의 주문행을 이 화면에서 수정할 수 없다.
- 중국 실기기, 테스트 Cloud B02 SQL 적용, 운영 배포/운영 DB 적용은 하지 않았다. 전체 B02 및 MVP 완료가 아니다.
