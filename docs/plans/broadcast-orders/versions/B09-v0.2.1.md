# B09-v0.2.1 · Cloud 사전검증 경로

- 기록: 2026-09-29. 상태: **진행 중**. 공통 문서 v2.2.0. 이전 [v0.2.0](B09-v0.2.0.md)의 테스트 프로젝트 스키마·비공개 버킷 적용을 유지한다.
- 테스트 프로젝트를 정확한 ref로 제한한 `cloud-auth-create.mjs`, `cloud-auth-check.mjs`, `cloud-adapter-check.mjs`와 새 `cloud-preflight-check.mjs`를 준비했다. 사용자의 작업 시점 승인 후 격리 프로젝트의 익명 로그인을 잠시 켜 두 Auth JWT를 발급했다. 직원 코드 참여·20건 동시 주문·멱등·권한 회수, Flutter 저장소→Cloud RPC, 별도 주문행·청구/QR 스냅샷·QR 실제 Storage 업로드/익명 다운로드 차단·무입금 발주 제외가 모두 통과했다. 즉시 익명 로그인을 다시 끄고 새로고침 후 off를 확인했다.
- 인증 설정을 바꾸지 않고 publishable key로 `cloud-public-barrier-check.mjs`를 실행했다. 실제 테스트 Cloud에서 익명 고객 테이블 조회와 직원 workspace RPC가 거절됐고, 두 private 버킷의 목록 응답에 객체명이 없었다. 빈 버킷 목록의 `200 []`는 권한 성공을 입증하지 않으므로 실제 객체 업로드 뒤 다시 검사해야 한다.
- Supabase의 새 `sb_secret_` 키는 JWT가 아니라는 공식 안내에 맞춰 고객 게이트웨이가 새 키를 `apikey` 헤더에만 넣도록 수정했다. 기존 service-role JWT는 Bearer로 계속 지원한다. 로컬 고객/게이트웨이 22/22, PostgREST HTTP 1/1, 참여 링크 위젯 2/2, Flutter 정적 분석·웹 빌드, 계획 검사와 문법 검사가 통과했다.
- 고객 게이트웨이의 기기 승인·증빙·분할 테스트 수취·발주·출고 Cloud 연속 실행은 아직 미실시다. 서버 전용 테스트 키는 채팅·저장소에 기록하지 않는다. 운영 DB·웹·실거래·고객 메시지 변경 없음.
