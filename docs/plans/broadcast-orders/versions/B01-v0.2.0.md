## 변경

- `202609280003_broadcast_paging.sql`: 초기 workspace의 고객·주문 전체 전송을 없애고, 상품 `has_orders`를 서버에서 계산한다. 고객 닉네임+ID 및 회차별 주문순번의 키셋 페이지 RPC를 추가한다. 권한과 판매자 경계를 각 페이지에서 다시 검사한다.
- Flutter 직원 화면: 닉네임 서버 검색, 중복 닉네임 위챗 관리정보 구분, 고객·주문 `더 보기`, 회차 전환 시 주문 첫 페이지 재조회. 고객 검색 250ms 지연과 늦게 온 검색 응답 폐기를 적용한다. 상품 정정 버튼은 현재 로드한 주문이 아닌 서버 `has_orders`로 판단한다.
- 공통 계획/화면·API/타입/시안 표기를 v2.2.0으로 묶었다. 시안은 고객 2명의 가상 검색·선택 흐름만 체험하며 실제 페이지 처리 성능의 증거가 아니다.

## 실제 검증

- PGlite SQL 11건: 검색 커서에서 닉네임 중복 분리, 주문 커서/순번, 빈 workspace 고객·주문, 상품 접수 잠금, 타 판매자 페이지 거절. 단일 연결 검증이다.
- 격리 Flutter 위젯 7건과 정적 분석, 전체 웹 빌드, 시안 6건, 버전 검사·diff 검사는 [작업표](../worklog.md)의 최종 실행 결과를 따른다. 서로 다른 환경을 혼용해 실제 HTTP 검증으로 주장하지 않는다.

## 미검증·제한

- 별도 테스트 Supabase/PostgREST·JWT와 두 실제 DB 연결의 경합, 실제 앱 프로세스 종료·재시작, 보조 참여 링크/회수의 end-to-end 검증은 남았다. 현재 환경에 해당 테스트 서버 설정과 CLI/컨테이너 런타임이 확인되지 않아 운영 서비스에 시험 마이그레이션을 적용하지 않았다.
- 고객·주문 페이지와 별개로 회차·상품 목록은 초기 workspace에서 받는다. 대규모 회차·상품 데이터 한도는 후속 실환경 부하 검증에서 조정한다.
- B02~B09 실제 기능, 운영 DB 적용·배포·실거래·고객 메시지는 수행하지 않았다. 기존 미커밋 변경은 보존했다.
