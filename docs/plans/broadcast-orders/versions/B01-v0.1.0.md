# B01-v0.1.0 · 첫 등록 체크포인트

- 기록 시점: 2026-09-28. 상태: **진행 중**. 공통 문서 묶음: v2.1.0. 요구 기준: [판매자 요구사항 v1](../requirements-v1.md).
- 단계: 고객·방송·상품과 직원 모바일 주문 접수. 현재 버전은 버전 체계 도입 시점의 로컬 구현 상태를 기록한다. B01 시작부터의 모든 중간 구현을 각각 별도 버전으로 소급하지 않는다.

## 구현 범위

- 신규 `broadcast_*` SQL/RPC와 Flutter 직원 입력: 방송 날짜/상태·기한, 신상 사전등록/특가 빠른등록, 소개 상품 공개·다중 코디, 고객 검색·독립 주문행·원 순번/원문·관리자 정정.
- 접수 전 상품 정정·소프트삭제/복구·공개순서, 공개 상품 정정 시 비공개 복귀, 접수 이력 상품 잠금.
- 명령별 UUID 멱등키, 응답 유실 시 동일 명령 재확인, actor·seller별 기기 기록을 통한 화면 재생성 복구.
- 30분 일회용 보조 참여 코드와 직원 접근 회수. 기존 로그인과 승인된 판매자 경계를 재사용한다.
- 운영 기능은 기본 feature flag 꺼짐. `202609230001`, `202609280001`, `202609280002` 방송 마이그레이션은 운영 DB에 적용하지 않았다.

## 검증 근거와 한계

- [작업표의 B01 기록](../worklog.md): PGlite 10건, 격리 Flutter 위젯 7건, Flutter 정적 분석·웹 빌드, 시안 클릭 경로를 각 구현 시점에 확인했다. 이 문서 작성으로 그 시험을 새로 반복했다고 표시하지 않는다.
- PGlite는 단일 연결이며 시안은 메모리 상태다. 별도 테스트 Supabase JWT→PostgREST→RPC, 두 접속 동시성, 실제 앱 재시작/참여 링크, 목록 페이지네이션, 약20건 현장 입력 속도는 미검증이다.
- B02~B09의 고객 인증·정산·입금·발주·입고·출고·알림은 실제 구현 완료가 아니다. 운영 배포·운영 DB 적용·실거래·고객 메시지 없음.
- 이 체크포인트는 현재 작업표와 문서를 잇는 기록이다. 기존 미커밋 변경을 포함한 Git 커밋·태그나 당시 전체 파일의 불변 스냅샷을 만들었다는 뜻은 아니다.
